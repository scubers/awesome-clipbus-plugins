# 实现与验证经验

结合当前 SDK 文档应用这些经验，不把某个模板版本的目录与代码写法推广为固定要求。

## 实现

- 先确定用户要的是被动识别、结果展示还是主动变换，再选择贡献方式，避免重复入口。
- 共用的数据与契约应能在所有使用端运行；运行端专用运算与页面代码分开。
- 校验实际输入与持久化数据，不用类型声明代替运行时验证；按 SDK 限额处理数据。
- 依据文档确认当前处理值与原始条目的区别、写入和提交时机、订阅与清理方式。
- 模板的演示业务、构建映射、预览样例、说明和测试需要一并检查，避免留下失效引用。

## 测试与预览

- 优先验证用户能观察到的结果、写入、状态与交互，沿用工程现有测试方式。
- 按业务覆盖正常输入、边界、非匹配或错误输入；需要时覆盖重复复制、状态清理和当前级联值。
- 展示可读文本的解码功能应覆盖合法非 ASCII、无效 UTF-8 和控制字符等业务向量。
- 预览使用真实组件与业务样例，检查主题、长内容、空态与按钮；不要求某个固定 scenario 文件路径。
- 使用工程自己的构建与验证，不能仅凭文件存在或代码形状判断功能完成。
- 确认宿主加载路径的构建产物已更新；真实宿主未验证的权限、提交与隔离行为不能声称已通过。
