# Clipbus 插件生成器

实现用户需要的真实插件功能。以当前官方模板了解工程组织，以实际安装的 SDK 文档确定接口，以目标插件自身的构建和行为测试验证结果。

## 环境与资料

- 需要 Node.js、npm、Git，以及访问模板与依赖源的网络。工作区不必是 Git 仓库，也不要求本地有模板或其他插件。
- 官方模板：`https://github.com/scubers/clipbus-template-plugin`。
- 在目标工程安装依赖后，先读 `node_modules/@clipbus/plugin-sdk/docs/README.md` 文档地图和 `node_modules/@clipbus/plugin-sdk/API.md`。若文档位置改变，从实际安装包的说明定位。
- API 签名、协议、manifest 字段和限额以安装版本的 SDK 文档为准。不要查看或修改 SDK 实现源码。
- 本 skill 使用本文件与 `references/` 中的说明，不依赖附带脚本、构建资产、其他 skill 或合集文件。

## 1. 理解需求与工作区

用户给定功能就实施；要求全自主时自行选一个实用选题。需要选题灵感时读 [topic-ideas.md](references/topic-ideas.md)。
确认目标位置与新建/扩展意图。默认新建目录可用 `clipbus-<topic>-plugin`，用户指定的位置和命名优先。

直接阅读当前工作区的实际文件：空目录可以新建；当前目录已有插件就按用户意图扩展；合集中查看相关插件的 manifest、README 和业务代码，按真实职责避免重复。
不依赖目录名称或 Git 跟踪状态识别插件。同职责的功能优先并入，用户明确要求独立插件时遵从。

## 2. 获取模板参考

新建时，用 Git 将官方模板获取到工作区外的临时目录，阅读它当前的 README、工程说明、manifest、package.json 及相关构建配置。
用户指定模板版本或来源时遵从，并记下实际来源与 commit。

根据当前模板的真实内容决定如何创建目标工程：可从模板复制起步，再按用途清理演示；也可仅参考所需部分。
目标已有用户文件时保留现有内容，不用模板整体覆盖。完成后清理本次创建的临时模板，不要求工作区长期保存模板副本。

不要预设模板的源码路径、预览入口、构建脚本名称、SDK 版本或 manifest schema。
模板中的构建映射、说明和测试可能专为演示服务，需要按新插件的实际能力调整，不能直接当成通用基建。
扩展已有插件时，先读现有工程，只在需要参考时获取模板，不重新初始化或顺带升级 SDK。

## 3. 安装依赖并读取 SDK

在目标插件目录运行 `npm install`，读取实际安装版本的 SDK 文档地图、API 参考以及本次能力涉及的主题。
先确认支持的贡献方式、manifest 声明、运行环境与权限、数据与限额、调用与提交语义，再写实现。
[architecture.md](references/architecture.md) 提供阅读资料时应回答的问题，不保存另一份接口规范。

模板示例、旧插件和本 skill 的经验与安装版本文档冲突时，以安装版本文档为准；不能把历史字段或代码形状作为新工程的硬性要求。

## 4. 实现功能

按用户需求选择贡献方式，仅实现需要的能力。已有卡片展示与复制足够时，不再增加相同用途的 Action；没有展示需求时不强加卡片。

按目标工程当前的组织方式维护 manifest、运行入口、构建配置、实际产物、预览与测试之间的一致性。
命名空间、权限和数据写入声明按安装版 SDK 要求设置，业务依赖按需添加。
有卡片时使用真实组件和业务样例预览，遵守当前 SDK 的主题、宿主布局和高度机制。

实现与测试的经验见 [authoring-guide.md](references/authoring-guide.md)。这里不提供代码生成器或通用构建脚本，具体接线由 Agent 根据当前工程和文档完成。

## 5. 运行工程自身的验证

先读目标工程的 package.json 和开发说明。有 `npm run verify` 时优先运行；没有时执行该工程实际提供的相关 manifest 校验、类型检查、lint、构建与业务测试，并按 SDK 文档补齐本次必要的验证。

保留有效的现有测试，为本次能力覆盖正常输入、边界和非匹配情况，检查真实输出或副作用。
遇到失败先查根因，不通过删断言、跳过检查或改成源码字符串匹配来换取通过。

不要用固定目录、README 字数、插件 id 命名偏好或某个历史 schema 版本作为额外验收门槛。
模板变化时调整当前工程实现，不为了迁就 skill 内置检查而退回旧结构。

新增或修改卡片时，运行工程当前的预览方式检查实际组件、样例、主题与交互。
确认用户宿主实际加载的目录已有最新构建产物；源码合并或移动不会自动重建。预览与模拟宿主未覆盖的真实宿主行为，交付时如实说明验证范围。

## 6. 文档与交付

更新插件自己的 README，说明真实功能、用法与开发命令。面向用户的插件文案使用英文，命名清楚一致。
合集已有插件索引时按其现有格式更新；已有中英双索引时同步维护。独立插件不在父目录创建索引。

汇报插件路径、实现能力、实际运行的验证与结果；新建时注明模板来源和 commit，无需强制生成特定格式的追溯文件。

## 分发与维护

将 `SKILL.md` 和 `references/` 一起放在 `clipbus-plugin-generator/` 中即可独立分发。
经验只记录可复用的判断依据，不复制 SDK 的完整 API、限额表或模板目录清单，不把更新 skill 作为完成插件的前置条件。
