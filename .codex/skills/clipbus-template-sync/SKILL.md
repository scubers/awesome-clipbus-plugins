# Clipbus 插件升级

按用户指定的目标与范围升级既有插件。官方模板提供工程参考，实际安装的 SDK 文档提供接口依据，目标插件自身的构建与行为测试验证迁移结果。

## 环境与资料

- 需要 Node.js、npm、Git，以及访问模板和依赖源的网络。目标插件不必位于 Git 仓库内。
- 官方模板：`https://github.com/scubers/clipbus-template-plugin`。按需获取到工作区外的临时目录，不在目标工程维护长期模板副本。
- 安装依赖后先读 `node_modules/@clipbus/plugin-sdk/docs/README.md` 和 `node_modules/@clipbus/plugin-sdk/API.md`，再按文档地图读迁移指南、变更记录和相关主题。文档位置改变时从实际安装包说明定位。
- API 签名、协议、manifest 字段与限额以对应安装版本的 SDK 文档为准。不要查看或修改 SDK 实现源码。
- 本 skill 仅使用本文件和 `references/`，不依赖合集文件、generator、附带脚本或构建资产。

## 1. 确认目标与当前基线

直接阅读用户指定插件的说明、manifest、package.json、锁文件与相关实现，确认要升级的插件和目标版本。
独立插件按自身目录处理；合集只纳入用户指定范围内的真实插件，不按目录名称或 Git 跟踪状态机械枚举。

记录 SDK 声明范围、锁定版本与实际安装版本。有需要时先在目标目录安装当前依赖，阅读当前 SDK 文档，并记录已有验证结果。
升级前保留可获得的旧版本 API 参考、迁移说明和相关文档，便于之后比较。缺少准确旧版本或旧模板基准时说明依据的边界，不臆造历史差异。

若目标使用 Git，查看已有改动以保护用户工作；没有 Git 也可升级。只修改本次范围，不要求清空工作区，不擅自 stash、删除嵌套仓库或重新初始化插件。

## 2. 获取官方参考并分析影响

用 Git 临时获取官方模板，阅读当前 README、工程说明、依赖声明与相关配置，记录实际来源和 commit。用户指定来源或版本时遵从。
SDK 升级目标以用户要求为先；未指定时结合官方模板、SDK 发布与迁移说明确定适合目标插件的版本，不顺带更新所有依赖。

需要在改动目标前阅读新版 SDK 文档时，可在独立临时目录获取对应版本的包，仅阅读它的公开文档。
对照目标插件、模板和新旧 SDK 的 API、变更记录、迁移指南及相关教程，判断实际影响。不能仅看版本号、方法数量或文档文件名。
[影响分析](references/propagation-analysis.md) 提供判断问题，不是固定文件清单。

说明必须迁移的契约变化、需要适配的工程配置、相关但可选的新能力，以及没有必要带入的模板演示改动。
模板没有新提交也可能有旧插件待升级；没有历史模板副本不妨碍根据目标插件现状分析。

向用户说明改动范围、兼容性影响和实施方式。已授权范围内继续完成；用户要求先审方案时遵从该边界。可选新能力按本次目标决定，不能仅因构建通过就忽略相关文档变化。

## 3. 迁移目标插件

按每个插件的实际组织方式修改依赖、manifest、实现与工程配置，保留插件身份、业务功能、用户数据和有效的现有测试。
依赖和配置按字段与用途合并，保留业务依赖、开发命令和各插件自己的锁文件，避免无关依赖改动。

不把模板整个文件或目录覆盖到插件，也不要求不同插件与模板的共享文件、scripts 或目录布局逐字一致。
模板构建逻辑可能服务演示，需要提取本次真正相关的变化并适配现有实现；新增、修改、删除的参考内容都要按实际用途判断。

更新依赖后在目标目录安装，确认实际安装的 SDK 版本并重新阅读该版本文档，再完成对应的代码、声明、预览、测试与文档迁移。
有持久化状态或交互变化时检查兼容处理。宿主不再支持某项现有能力时说明影响，不能用空壳、删测试或无关替代功能冒充迁移完成。

批量升级可先验证一个有代表性的插件，再将已确认的方法应用到其余目标；仍要阅读各插件差异并分别验证，不把试点的文件直接覆盖所有插件。
不为完成升级强制创建分支、worktree、子 Agent 或修改其他 skill。

## 4. 运行每个工程自身的验证

阅读每个目标的 package.json 和开发说明。有 `npm run verify` 时优先运行；没有时执行该工程实际提供的相关 manifest 校验、类型检查、lint、构建与业务测试，并按新版 SDK 要求补齐本次必要的验证。

保留原有业务向量，检查受迁移影响的真实输出、写入和交互。失败先定位根因，不能跳过检查、删断言或只检查源码字符串来换取通过。
构建通过不等于所有生命周期、权限或可选能力都已审查；结合文档确认迁移范围是否完整。

有页面或预览变化时检查真实组件与业务样例。确认用户宿主实际加载路径已有最新构建产物，源码合并或移动后按需重建。
逐插件记录实际运行的命令与结果；模拟宿主和预览不能证明的真实宿主行为，如实说明验证范围。
不要增加依赖固定路径、历史 schema、README 字数或跨插件文件逐字一致的额外验收器。

## 5. 文档与交付

按实际变化更新目标插件自己的说明；合集已有相关索引时沿用其格式维护，独立插件不在父目录创建索引。
汇报目标路径、SDK 的旧版本与实际新版本、模板来源与 commit、迁移内容和每个目标的验证结果。没有必要改动的目标说明依据，不制造无意义的同步差异。
清理本次创建的临时模板与参考包，不在工作区留下新的模板副本。

## 分发与维护

将 `SKILL.md` 与 `references/` 放在 `clipbus-template-sync/` 中即可独立分发，不需要同时安装其他 skill。
只沉淀可复用的判断经验，不保存某一版本的目录清单、SDK API 副本、限额数字或永久验证豁免。
